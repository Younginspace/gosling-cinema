起源：一段录屏和一个念头

故事开始于一个网站——shader.se。一家瑞典创意开发工作室的作品集，用复古 CRT 启动画面引导进入一条 3D 胶卷，每一帧是他们的一个项目。点击旋转、滚动切换，整个交互充满电影感。

看到的第一秒就觉得：这种胶卷形式太适合做演员作品集了。正好最近因为《挽救计划》电影对 Ryan Gosling 印象深刻——从 Drive 的沉默暴力美学，到 Blade Runner 2049 的赛博孤独，再到 La La Land 的浪漫失落，Barbie 的荒诞幽默，直到 Project Hail Mary 的星际热血——五部电影，五种完全不同的视觉风格，天然适合用不同的 shader 来呈现。

"先行动，从被激发灵感的创意开始。创意是原创-复刻融合微创新的螺旋上升。" — 开发者

于是打开终端，npm create vite@latest，项目名敲下 gosling-cinema。

眼前一亮：当 AI 看懂了录屏

最初的尝试是截图。把 shader.se 的几个关键画面截下来喂给 AI："帮我做一个类似的效果。" 结果还原度很低——截图丢失了太多信息：动画的节奏、过渡的缓动曲线、滚动的手感、元素之间的时序关系……这些在静态图片里全部消失了。

转机来自一个工具。朋友推荐了 AnyCap CLI，可以用 Gemini 理解视频内容。于是录了 shader.se 的操作录屏，让 Gemini 分析，生成了详细的逐帧文字描述：

AnyCap 生成的分析片段

"用户向下滚动时，无缝过渡：3D 电脑环境向上消退，一条弯曲的 3D 胶卷条从底部滚入视野。胶卷条在 3D 空间中弯曲，向观众方向'包裹'制造纵深感。垂直滚动 → 胶卷水平移动（联动滚动），有'加权'感，停止滚动时有 ease-in/ease-out，精确对齐到帧。"

把这份分析文档作为 prompt 喂给 Claude Code，效果截然不同。AI 理解了"镜头推进→胶卷旋转"的动态关系，做出了虽然不完全还原 shader.se、但"另一种效果还行"的交互方案——3D 旋转木马替代了直线胶卷，反而有了更强的深度感。

Lesson Learned

对于动态交互效果，视频 > 截图。录屏里包含了时序、缓动、物理感这些截图完全无法传达的信息。用 AI 理解录屏后生成的描述，比截图准确一个量级。

感动时刻：真实素材跑通了

技术框架搭好后，胶卷帧里放的还是空白占位符——灰色方块配着 DRIVE (2011) 的小字。效果可以验证，但感觉像是在看一个骨架。

然后开始找真实视频素材。从 YouTube 上找到每部电影的片段，用工具下载，剪辑成经典镜头，放进 asset/ 文件夹。<video> 标签嵌入胶卷帧，loop muted playsInline，刷新本地预览——

Drive 的霓虹粉红夜街画面在胶卷里循环播放，bloom shader 让灯光溢出画面边缘。向右滚，Blade Runner 2049 的橙色沙暴铺满视野，chromatic aberration 让画面微微错位。再滚，La La Land 的星空下两个人跳舞，深紫色的 tint 笼罩一切……

把真实视频素材放进 asset 文件夹，在本地预览成功的那一刻——是整个项目最有成就感的时刻。 — 开发者

从骨架到血肉，只差了"真实内容"这一步。但这一步带来的感受差异是巨大的。

后处理管线

Five-pass 后处理链，每一层叠加不同的视觉效果： 

RenderPass → UnrealBloomPass → DistortionShader → FilmShader → OutputPass
                │                    │                  │
            光晕溢出            鼠标液态扭曲      胶片颗粒/扫描线/暗角/色散/色调

设计决策：每部电影有独立的 6 个 shader 参数，切换时用 lerp(current, target, 3.0 * dt) 平滑过渡。说实话视觉上差异不算特别明显，但细看能感受到——Drive 的 bloom 是 1.5（霓虹溢出感），Barbie 只有 1.0（明亮但不刺眼）；Blade Runner 的 noise 是 0.2（粗糙胶片质感），La La Land 只有 0.06（干净浪漫）。

人机协作：录屏驱动的 Vibe Coding

这个项目的协作模式有一个鲜明特点：录屏是核心素材，不是截图。

传统的"给 AI 看截图让它写代码"在处理动态交互时有天然缺陷。截图是时间的切片，丢失了动画、过渡、物理感这些构成"体验"的核心元素。而这个项目的目标恰恰就是体验——不是做一个静态页面，而是做一个"有手感"的滚动交互。

解决方案是引入 AnyCap CLI 作为中间层： 

录屏 (mp4) → AnyCap + Gemini → 结构化描述 (md) → Claude Code → 代码

这条管线把"我想要这种效果"从模糊的视觉印象转化成了精确的技术规格。比如 AnyCap 分析出的"有加权感，停止滚动时有 ease-in/ease-out"直接对应了 Lenis 的 easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t))。

协作模式

不是"看截图抄作业"，而是"看录屏理解意图，然后做出自己的版本"。最终产出的 3D 旋转木马和 shader.se 的直线胶卷长得完全不一样——但那种电影感和沉浸感是对的。

踩过的坑

1. Blender 模型的法语命名

Commodore PET 2001 的 GLB 模型来自社区创作者（法国人）。traverse 模型时发现屏幕网格叫 Plan_7，玻璃叫 vitre——如果不打印所有 mesh 名称，根本找不到需要替换材质的部分。

2. CRT Boot 的时序问题

Boot screen 是 HTML overlay，3D 场景在下面异步加载。如果 boot 动画播完时 3D 场景还没准备好，就会看到一帧空白。解决方案：boot 完成时不直接淡出，而是先 await filmScene.ready，确认模型加载完毕、第一帧渲染完成后，再 fadeOut()。

3. 无限循环 Carousel 的旋转漂移

用户连续滚动时，targetRotation 会无限累加。虽然 %360 可以归一化角度，但 clone 帧的数量有限（PAD=5），角度超过克隆范围就会穿帮。最终方案：scheduleNormalize()——在动画稳定 500ms 后检测累计漂移，如果超过一整圈就瞬移回标准位置。

收获

01 — 先行动

看到 shader.se 被击中的那一刻就开始动手。不必等到完美方案，创意本身就是螺旋上升的——先复刻，再理解，最后变成自己的东西。

02 — 不完全还原也是一种成功

3D 旋转木马和 shader.se 的直线胶卷长得完全不一样。但"另一种效果还行"比"完美复刻"更有价值——它变成了你自己的作品，而不是别人的翻版。

03 — 真实内容是魔法

占位符和真实视频素材之间的差距，不是技术差距，是情感差距。当 Drive 的霓虹夜街在 bloom shader 里溢出光晕的那一刻，这个项目从"技术 demo"变成了"作品"。

04 — CRT Boot 不只是装饰

它掩盖了 3D 模型和视频的加载时间，把等待变成了体验的一部分。好的 loading 不是进度条，是叙事。

05 — Shader 参数是最低成本的氛围切换

6 个浮点数（bloom, chromatic, noise, vignette, scanline, sepia）+ 3 个 tint 值，就能让同一个画面从霓虹朋克变成赛博荒漠。改参数比改模型、改灯光便宜一百倍。
